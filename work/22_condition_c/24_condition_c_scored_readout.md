## 종합 점수의 구조적 공백

평가셋 v2 의 **10문항**은 `key_facts_for_summary` 가 비어 있고,
**14문항**은 `expected_fields` 가 비어 있다. 채점기는 전자에
요약 충실도 **1.0(만점)** 을 주고, 후자는 가중치에서 **제외**한다.

둘 다 빈 문항에서 종합 점수는 이렇게 붕괴한다.

종합 점수는 **분류 정답 여부의 1차식으로 붕괴한다** — 요약 축이 상수 만점이
되고 필드 축이 빠지면서, **분류를 틀려도 0 이 아닌 하한**을 받는다.

**분류를 틀려도 0.385 를 받는다.** 그리고 해당 10문항은
「정보 부족」 gold **전부**다 — 기권을 시험하려고 만든 칸에서 요약 축이
공짜로 만점을 준다. 1.0 이라는 처리가 틀린 것은 아니다(덮을 사실이 없으면
놓친 것도 없다). 문제는 그 만점이 **한 칸에만 몰려 있다**는 것이고, 칸을
가로질러 평균을 내는 순간 그 칸이 실제보다 좋아 보인다. 부록 H 가 분류
축에서 찾은 것과 같은 종류의 구멍이 요약 축에도 있다.

해당 문항: 8, 9, 14, 15, 22, 29, 30, 37, 38, 43, 45, 46, 51, 53

## note 축 — 종합 점수가 재지 않는 곳

종합 점수는 분류·필드·요약 세 축으로만 계산된다. **`note` 는 어디에도 없다.**
note 는 게이트(기권 적절성)로만 들어가고, 그 게이트는 특수 문항에만 적용된다.
그래서 note 가 무너져도 종합 점수는 떨어지지 않는다. 따로 봐야 한다.

**열거는 `note` 를 비운다.** 이것이 이 실험에서 가장 값비싼 발견이다.
카테고리를 메뉴에서 고르게 하자 모델이 출력을 그 선택에 쓰고 설명을 그만뒀다.
특수 문항(정보부족·범위밖)에서 **note 가 곧 산출물**이다 — 상담원에게 다음에
무엇을 더 물어야 하는지 알려 주는 칸이기 때문이다. note 가 비면 분류가 맞아도
응답은 쓸모가 없다.

그래서 조건 C 는 **종합 점수는 오르고 게이트 통과율은 내린다.** 이 프로젝트의
규칙은 「게이트 먼저, 랭킹 나중」이므로, 이 둘이 엇갈릴 때 따라야 할 쪽은
게이트다. 조건 C 를 그대로 배포 프롬프트로 삼을 수 없다는 뜻이다.

조건 B 가 note 를 가장 길게 쓰게 만든다(규칙 블록이 note 에 무엇을 적으라고
명시하기 때문이다). 다음 조건 D 는 **열거(카테고리) + 규칙(note)** 을 함께
주고, 부록 M.4 가 지적한 과잉 기권을 막을 기권 기준을 덧붙여야 한다.
